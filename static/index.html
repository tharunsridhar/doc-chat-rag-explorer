How RAG actually works

Every stage below is a real step in the pipeline, not a simplification:

1

Chunk

Long text is split into overlapping pieces (chunk_size=500, overlap=50) so each piece is small enough to embed meaningfully.

→
2

Embed

A local model (all-MiniLM-L6-v2) turns each chunk into a vector — numbers that capture its meaning.

→
3

Store

Vectors go into a Chroma vector database, ready to be searched by similarity instead of by keyword.

→
4

Retrieve

Your question is embedded the same way, then Chroma returns the closest-matching chunks — this alone is retrieval, no LLM involved yet.

→
5

Augment

The retrieved chunks are stitched into a prompt as "context" alongside your actual question — this is the "augmented" in Retrieval-Augmented Generation.

→
6

Generate

That augmented prompt is sent to Groq's LLM, which answers using only the context it was given.

1. Build the index

Paste some text or upload a .txt file. This runs steps 1-3 (chunk → embed → store) and creates a fresh, in-memory vector store just for this document.
